## Integrity and collision boundaries

Embedded artifact result integrity, saved-report top-level integrity and successful saved batch-result integrity must be `unverified` (`scripts/validate_x04_offline_evidence.py:25-26`; `scripts/validate_x04_review_report.py:32-33,77,111`). The packet generates its own scope, valid flag, external-path flag and integrity at lines 103-107. Input packet fields with those output names are opaque; consumers must read the validated output rather than promote raw input annotations into proof.

Saved-report extension assertions cover provenance-like fields, opaque paths, a false input valid flag and fixed output scope (`server/tests/test_x04_report_validator_extension_scope.py:10-36`). The same file requires known integrity forgery to refuse at lines 39-44. Those tests target saved reports, not every packet nesting level. Packet cross-binding tests assert only the generated external-path flag and integrity (`server/tests/test_x04_packet_cross_binding.py:27`).

Explicit coverage gaps: no packet-specific assertion here enumerates output-name collisions on the raw packet; no cited packet test pins the extra-count-key versus extra-dependency-metadata distinction. The unexecuted local schema/type draft does not close these gaps. Future recognition of an opaque name can change compatibility, and a new metadata key can change whole-row equality. These are schema-review considerations, not newly established product blockers or requests to expand the frozen test packet.
